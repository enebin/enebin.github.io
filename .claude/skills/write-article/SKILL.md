# write-article — enebin.log 글 작성

인자로 받은 **주제**로 `_posts/`에 새 글 한 편을 완성한다. 조사 → 초안 → 그림 → 윤문 → 로컬 확인 순으로 진행한다.

주제가 비어 있으면 사용자에게 물어보고 멈춘다. 그 외에는 중간에 확인을 요청하지 않고 끝까지 진행한다.

## 1. 조사

주제가 특정 원문(기사·논문·공식 문서·릴리스 노트)을 가리키면 `WebFetch`로 원문을 직접 읽는다. 링크가 없으면 `WebSearch`로 1차 출처를 찾아 읽는다. **원문에 없는 수치·인용은 쓰지 않는다.** 수치를 쓸 때는 원문 표현을 그대로 옮긴다.

주제가 필자의 경험·의견이면 조사를 생략하고, 사용자가 준 맥락만으로 쓴다. 사실 확인이 필요한 빈칸이 생기면 지어내지 말고 그 대목을 빼거나 사용자에게 묻는다.

## 2. 구조 잡기

글을 쓰기 전에 뼈대를 먼저 정한다.

- 도입 1~3문단: 독자가 겪는 구체적인 곤란한 상황에서 시작한다. "요즘 ~가 화제다" 같은 일반론으로 열지 않는다.
- `<!--more-->` (도입 직후에 넣는다. 목록 페이지 요약이 여기서 잘린다)
- 본문 섹션 4~6개, 각각 `##` 제목. 제목은 명사 나열이 아니라 그 절에서 하는 말로 짓는다. 예: "왜 하던 대로 하면 안 되나"
- 마지막 섹션은 정리. "결론"이라는 제목은 쓰지 않는다.

그림은 3~4장, 서로 다른 섹션에 배치한다. 커버 이미지는 선택이다.

## 3. 초안 작성

파일: `_posts/YYYY-MM-DD-{영문-슬러그}.md` (날짜는 오늘, 슬러그는 소문자 하이픈)

front matter는 이 형식을 그대로 지킨다.

```yaml
---
title: 글 제목
description: 한 문장 요약. 목록과 SEO에 쓰인다.
category: 개발
reading_time: 9분
image: /assets/images/{슬러그}-cover.svg
---
```

- `category`: `개발` / `생각` / `기록` 중 하나. 애매하면 `기록`.
- `image`: 커버를 만들었을 때만 넣는다.
- `reading_time`: 4단계에서 계산한 값.

### 분량

본문 **공백 제외 4,000~5,000자**. 500자/분 기준으로 8~10분이다. 이 범위를 벗어나면 늘리거나 줄인다. 확인 방법:

```bash
python3 -c "import re,sys; b=open(sys.argv[1],encoding='utf-8').read().split('---',2)[2]; b=re.sub(r'<figure>.*?</figure>','',b,flags=re.S); n=len(re.sub(r'\s','',b)); print(n, '자 →', round(n/500), '분')" _posts/파일명.md
```

출력된 분을 `reading_time`에 적는다.

### 문장

고등학생이 막힘없이 읽을 수 있어야 한다.

- 한 문장에 한 가지만 담는다. 문장이 두 줄을 넘어가면 자른다.
- 전문 용어는 처음 나올 때 반 문장으로 풀어준다. 그다음부터는 그냥 쓴다. 용어 자체를 피하지는 않는다.
- 쉽게 쓴다고 늘어놓지 않는다. 비유를 덧붙이거나 같은 말을 반복해서 쉬워지는 게 아니라, 군더더기를 빼서 쉬워진다.
- 중요한 문장은 `**굵게**`. 한 섹션에 한 번 이하.
- 원문에서 인용할 문장이 있으면 `>` 인용문으로 한 번 정도 쓴다.
- 이모지를 쓰지 않는다. 불릿은 정말 목록일 때만 쓴다.

## 4. 그림

`assets/images/{슬러그}-{이름}.svg`로 저장하고 본문에 이렇게 넣는다.

```html
<figure>
  <img src="/assets/images/{슬러그}-{이름}.svg" alt="그림이 무엇을 보여주는지 한 문장">
  <figcaption>그림이 말하는 결론 한 줄.</figcaption>
</figure>
```

그림은 글의 장식이 아니라 **글로 설명하기 번거로운 관계**를 대신 보여주는 것이다. 비교(A vs B), 층위, 순환, 단계별 흐름이 좋은 후보다. 본문 문장을 그대로 그림에 옮겨 적은 것은 그림이 아니다.

SVG는 블로그 스타일에 맞춘다. 기존 파일(`assets/images/edd-three-layers.svg`)을 먼저 읽고 같은 어법으로 만든다.

- `viewBox="0 0 1200 700"`, `role="img"`, `aria-label` 필수
- 색: 배경 `#ffffff`, 글자 `#191919`, 보조 글자·선 `#6d6d6d` / `#e9e9e9`, 강조는 `#e34f32` 하나만
- 글꼴: `.t { font-family: 'Apple SD Gothic Neo','Malgun Gothic','Noto Sans KR',Helvetica,Arial,sans-serif; }`를 `<style>`에 넣고 모든 `text`에 `class="t"`
- 본문 글자 17~19px, 항목 제목 30px, 라벨 15~16px
- 그라디언트·그림자·둥근 모서리·아이콘을 쓰지 않는다. 사각형, 선, 화살표, 글자만 쓴다.

## 5. 윤문

초안이 끝나면 `humanize-korean` 스킬을 `Skill` 도구로 호출한다.

- 넘길 것: front matter를 **뺀** 본문 전체
- 지시에 포함할 것: `<figure>` 블록의 HTML 태그와 `src`·`alt`는 건드리지 말 것, `<!--more-->` 위치 유지, 마크다운 제목 구조 유지
- 결과를 원본 파일 본문에 반영한다. front matter는 그대로 둔다.

윤문 후 분량이 범위를 벗어났는지 3단계의 명령으로 다시 재고, `reading_time`을 맞춘다.

## 6. 로컬 확인

`preview_start`로 `jekyll` 서버를 띄우고 `http://localhost:4000/posts/{슬러그}/`를 연다. `read_page`로 제목·본문·그림이 다 나오는지, `preview_logs`로 빌드 오류가 없는지 본다. 그림이 깨져 보이면 `read_network_requests`로 404를 확인한다.

## 7. 보고

- 파일 경로, 글자 수와 읽는 시간, 만든 그림 목록
- 윤문에서 손댄 곳 요약
- 사실 확인이 필요해 비워둔 대목이 있으면 여기서 밝힌다

커밋은 하지 않는다. 사용자가 따로 요청할 때만 한다.
